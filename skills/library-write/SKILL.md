# library-write: SPEC대로 책을 쓴다

이 스킬은 `books/<id>/SPEC.md`가 확정된 뒤에만 쓴다. 산출물은 빌드된 책(dist/index.html), 갱신된 `STATUS.md`와 `UNVERIFIED.md`, 그리고 단계마다의 커밋이다. 출간(검수·서가·업로드)은 하지 않고 `library-publish`로 넘긴다.

## 0. 준비 (매번)

1. **엔진 저장소:** `/home/claude/history-engine`을 쓴다. 없으면 `gigabgim59-sketch/history-engine`을 붙여(add_repo) 받는다. 붙일 수 없으면 사용자에게 소스 묶음과 SPEC을 첨부해 달라고 한다.
2. **읽는다:**
   - `LIBRARY.md`(특히 §2, §6, §10)
   - `DEFECTS.md`(공통 결함과 이 책의 결함)
   - `books/<id>/SPEC.md`, `STATUS.md`, `UNVERIFIED.md`
3. **멈출 조건:**
   - SPEC 머리에 확정 날짜가 없으면 멈추고 `library-plan`으로 돌아간다.
   - 집필 중 SPEC과 다르게 써야 할 이유가 생기면, 쓰기 전에 묻는다.
4. **작업 폴더:**
   - 새 책은 `engine/`의 파일을 `books/<id>/`에 복사하고 `bash restore.sh`를 실행한다. 이 책에만 필요한 템플릿 수정은 그 폴더에서 하고 STATUS의 `엔진 수정` 칸에 적는다. 다른 책에도 쓸 만한 수정이면 `engine/`에도 넣고 DEFECTS나 개정 기록에 남긴다.
   - 이어 쓰는 책은 STATUS의 `다음 할 일`부터 시작한다.
5. **사용자에게 한 문장:** 무엇을 어디까지 할지 알린다. 진행은 작업 목록으로 보이고, 단계 사이의 말은 줄인다.

## 1. 뼈대

0. **엔진 변경:** SPEC의 '엔진 변경'에 적힌 것을 먼저 한다. 본문을 쓰기 전에 엔진을 넓히고 시험 빌드로 확인한다.
1. `data.mjs`: SPEC의 META, 부, 축(겹), 힘, 장 종류(KINDS)와 절 이름(SLOTH), 줄기, 무대, 집단, 분량 목표(`META.len`)를 옮긴다. `META.pfx`(브라우저 저장소 접두, 책 id), `META.evalw`(평가어 목록), 관점 책이면 `META.outerMin`도 넣는다(engine/README).
2. `events.mjs`: 장마다 다음 칸을 채운다.
   - `id`, `p`(부), `t`(제목), `y`(연도 표기), `yr`(정렬용 숫자), `r`(무대)
   - `pl`(장소: [이름, 경도, 위도]. 지도를 끈 책은 비워 둔다)
   - `w`(등급), `g`(힘), `nx`(이어지는 장), `kd`(종류), `q`(물음), `s`(핵심 요약)
3. `links.mjs`: `nx`마다 `'원인>결과': '왜 이어지나 한 문장'`을 쓴다. 이유는 사실이어야 하고, 요약을 되풀이하지 않는다.
4. **지도:** `geo.mjs`(투영과 범위)와 `data.mjs`의 `SEAS`를 그 책에 맞게 쓴다. 장소가 없는 단위의 책은 `META.nomap`(필요하면 `nolanes`)으로 끄고, `pl`은 빈 값으로 둔다.
5. **복사해 온 문구:** 템플릿과 인쇄 도구에서 앞 책 고유의 문구를 이 책 것으로 바꾼다. `checks/residue_words.txt`의 목록과 `META`의 `debl`·`mapnote`·`srcnote`를 확인한다. DEFECTS P-07이 열려 있는 동안은 `print/make.mjs`에 박힌 절 이름, 일러두기의 수, 표제지 문구, 장 참조 정규식, 맺음 제목도 고친다.
6. `node build.mjs`가 통과해야 한다. 연결·참조·종류 검사가 빌드에 들어 있다. 통과하면 커밋한다.

## 2. 보정 장 (새 책, 또는 새 변형을 쓸 때)

1. SPEC이 정한 보정 장 두 개(핵심 하나, 주요 하나)를 먼저 끝까지 쓴다.
2. 잰다:
   - 장 분량(`node build.mjs` 출력)
   - 문단 수와 문단당 글자 수
   - 절별 비중
   - 사실 확인에 든 검색 수
3. STATUS의 `보정` 칸에 적고, 나머지 장의 문단 계획을 정한다. 예: "핵심 장 = 문단 28개 × 약 190자".
4. 새 변형이면 두 장을 사용자에게 보여 주고 방향을 확인받는다. 이것만 예외로, 본문을 사용자에게 보낸다.

## 3. 부 단위 집필 (한 부씩 반복)

1. **사실 메모:** 날짜, 숫자, 인용, 인명을 먼저 정리한다. 확실한 것만 쓴다(LIBRARY §6.2).
   - 확신이 없으면 빼거나 '전해진다'로 쓰고, `UNVERIFIED.md`에 올린다. 올릴 때는 장, 문장, 의심 이유, 확인 방법을 적는다.
   - 최근 사실은 웹으로 확인하고, 진행 중인 일은 '(진행 중)'으로 표시한다.
2. **본문:** 파일은 `body_p<N>a.mjs`, `body_p<N>b.mjs` …이고, 내보내는 이름은 `B<N>A`, `B<N>B` …이다.
   - 초고는 SPEC의 초고 목표(기본: 핵심 105~112%, 주요 108~116%, 보조 110~120%)로 쓴다. 하한에 맞춰 쓰지 않는다.
   - 수식, 유도, 수치 예제, 표는 다시 계산해 확인한다. 코드로 셈할 수 있으면 코드로 셈하고, STATUS에 기록한다(LIBRARY U5).
   - 다른 장은 `[[id]]`로 가리킨다. 앞에서 이미 쓴 사실은 다시 설명하지 말고 그 장을 가리킨다.
   - 해석은 이름 붙은 학자·학파·목소리에 돌린다. 갈림에는 학자 이름과 연도를 본문에 단다(작품 목록에만 두지 않는다). 논변의 타당성 같은 판정도 해석이다(LIBRARY U4).
   - 원전 인용을 옮길 때 기존 번역을 참고했으면 출처에 그 번역을 밝힌다(LIBRARY §3.9).
   - 평가어 목록(SPEC)의 말은 서술자 문장에 쓰지 않는다. 귀속은 이름 붙은 목소리로 하고, 한 공식("이 서사에서" 등)을 장당 두 번 넘게 쓰지 않는다.
   - 관점 책은 LIBRARY §6.5를 지킨다. 매 장 바깥 점검을 두고, 폭력 주장은 귀속과 맥락과 피해를 함께 쓰고, 실행 정보는 쓰지 않는다.
3. **분량:** `node chk.mjs`로 등급별 하한을 확인한다.
   - 모자라면 그 장에 실제로 빠진 사실, 목소리, 해석을 찾아 `node addp.mjs sp/x.json`으로 보강한다. 형식은 `[{c, s, t, at?}]` 또는 `[{c, s, after, add}]`이다.
   - 보강 전에 같은 사실이 다른 장에 있는지 찾는다. 채우기용 일반론은 쓰지 않는다.
4. **인물:**
   - `sp/p<N>rows.txt`에 `id|이름|별칭|원어|생|몰|진영|한줄|설명|` 행을 쓴다.
   - `sp/p<N>at.txt`에 `장|id:이 장에서 한 일` 행을 쓰고, 금지 규칙은 `sp/p<N>deny.txt`에 둔다.
   - `python3 tools/genp.py N sp/p<N>rows.txt sp/p<N>at.txt sp/p<N>deny.txt`로 `people_p<N>.mjs`를 만든다.
   - 빌드한 뒤 `node atcheck.mjs <접두>`가 비어야 한다. 문맥은 `node tools/ctx.mjs <장> <낱말>`로 본다.
   - 동명이인과 우리말 낱말과 같은 짧은 이름은 전체 이름으로 쓰거나 PDENY로 막는다.
   - 역사가·연구자는 해석자로만 나오면 인물 사전에 넣지 않는다. 장의 주체로 나오면 넣고, 두 역할을 한 항목에 적는다(LIBRARY §6.3).
5. **부 머리:** `part<N>.mjs`에 `P<N>`(부 서두·힘별 정리·무대별 배경·요약 세 문단), `GROUP_CH<N>`, `AXCH<N>`를 쓴다.
6. **용어와 서가:**
   - 용어는 `terms.mjs`의 `[표제, 풀이, 분야]`, 서가는 `books.mjs`의 `BOOKS`와 장별 근거 `BK`에 넣는다. `python3 app.py terms|books|bk <파일>`로 덧붙이거나 `tools/books_src.py`를 쓴다.
   - 서지는 원서만 싣는다(LIBRARY §3.9). 실재를 확인하지 못한 서지는 넣지 않거나 UNVERIFIED에 올린다. 확인은 검색 결과나 출판사·도서관 목록으로 한다. 기억만으로 저자·연도·제목을 확정하지 않는다.
7. **빌드와 검사:**
   ```
   node build.mjs && python3 font.py dist/index.html
   python3 t1.py <스크린샷 폴더>        # 390 [] / 1280 []
   node checks/lengths.mjs              # 하한 미달과 표시값
   node checks/voice.mjs                # 평가어·공식 반복·갈림 귀속
   node checks/residue.mjs dist/index.html   # 메뉴·장 화면 잔재
   node checks/consistency.mjs          # 책 안 연도 엇갈림, 요약↔본문
   ```
   검사가 보고한 '확인할 것'은 그 부를 닫기 전에 하나씩 본다.
8. **기록:**
   - STATUS의 장별 표(상태·분량)와 `다음 할 일`을 갱신한다. 이 책에서 생긴 이름 규칙과 표기 결정도 STATUS에 적는다.
   - 커밋한다. 저장소가 없으면 outputs에 소스 묶음을 둔다. 작업 환경은 사라질 수 있으니, 부 하나를 끝낼 때마다 저장한다.
9. **사용자에게:** 부가 끝날 때 한두 문장으로 알린다(어디까지, 특이 사항). 중간 파일은 보내지 않는다.

## 4. 마무리

1. **맺음(`concl.mjs`):** 책의 물음에 답한다. 축(겹)과 줄기로 다시 모으고, 남은 물음을 적는다. 교훈을 노리지 않는다.
2. **머리말(`META.intro` 등):**
   - 책의 물음, 단위와 입장 기준, 구성과 비중, 시선, 용어 원칙을 밝힌다.
   - 관점 책이면 누구의 눈인지와 바깥 점검이 어디 있는지 밝힌다.
   - 화면판과 인쇄판에 다른 것이 있으면 머리말도 판마다 맞춘다.
3. **선택 모듈:** SPEC이 켠 것만 만든다(요소별 변천, 읽는 법, 썸네일 등). 끈 모듈은 메뉴에서 숨겨졌는지 확인한다.
4. **인쇄본:** `node print/make.mjs` 다음 `python3 print/render.py`. 결과는 `print/<pfx>_a4.pdf`이고, `python3 checks/pdfcheck.py print/<pfx>_a4.pdf`로 확인한다. DEFECTS P-01~P-07이 열려 있으면 그 항목은 실패로 나온다. 이 실패를 보고에 적되, 정비에서 인쇄 도구를 고치기 전까지는 이것 때문에 출간을 막지 않는다.
5. **자체 점검 기록:** STATUS에 다음을 적는다.
   - 분량 통계(등급별 최소·중앙·최대)
   - 미확인 목록의 남은 수
   - 검사 결과
   - 알려진 약점

## 5. 넘겨주기

- STATUS에 "집필 완료, 검수 전"이라고 적고 커밋한다.
- 사용자에게 알린다. 무엇이 끝났는지, 다음은 독립 검수와 출간(`library-publish`)이라는 것, 미확인 목록이 몇 건인지.
- 출간은 사용자의 확인을 받은 뒤 `library-publish`로 한다.

## 하지 말 것

- SPEC 확정 없이 쓰기, SPEC과 다른 구조로 쓰기
- 하한을 목표로 쓰기, 같은 말 되풀이로 분량 채우기
- 기억만으로 서지·연도·인용을 확정하기, 출처 지어내기
- 도구 결함을 손으로 우회하고 문서에만 적기. 엔진을 고치고 DEFECTS에 남긴다
- 앞 책의 문구·자리표시를 그대로 두기. 복사한 템플릿의 책 고유 문구는 처음에 모두 바꾼다
- 작업 환경에만 소스를 두기
