# library-publish: 검수하고, 고치고, 서가에 올린다

산출물은 다음과 같다.
- 검수 기록과 결함 처리(`DEFECTS.md`)
- 출간본: `<제목>.html`, `<제목>_A4.pdf`
- 갱신된 서가(`library/books.json`, 서가 HTML)
- 업로드 커밋

그 책의 확신도 높은 결함이 열려 있으면 출간하지 않는다(LIBRARY U10). 공통 결함(E·P·L)은 막지 않고 보고한다.

## 0. 준비 (매번)

1. **엔진 저장소:** `/home/claude/history-engine`을 쓴다. 없으면 `gigabgim59-sketch/history-engine`을 붙여 받는다. 서가 저장소 `gigabgim59-sketch/history-all`도 필요하면 붙인다(add_repo, 쓰기 권한).
2. **읽는다:**
   - `LIBRARY.md`(§2, §6, §7.3, §9, §10)
   - `DEFECTS.md`
   - `books/<id>/SPEC.md`, `STATUS.md`, `UNVERIFIED.md`
3. **모드를 정한다:**
   - **출간:** STATUS가 "집필 완료, 검수 전"인 새 책.
   - **정비:** 이미 서가에 있는 책의 결함을 처리한다. 대상은 사용자가 정한 책이거나 DEFECTS의 열린 항목이다.
   - 소스가 없는 책(book.json만 남은 책)은 §6의 방법으로 다시 빌드한다.

## 1. 기계 검사 (모두 통과해야 다음 단계)

책 폴더에서 실행한다.
```
node build.mjs && python3 font.py dist/index.html      # 연결·참조·종류·인물 진영 검사 포함
node checks/lengths.mjs        # 등급별 하한, 장 머리 표시가 계산값과 같은가
node checks/residue.mjs dist/index.html   # 메뉴의 모든 화면: 자리표시·다른 책 문구·undefined·NaN, 빈 화면 메뉴
node checks/voice.mjs          # 서술자 문장의 평가어, 한 공식의 반복, 학자 없는 갈림
node checks/consistency.mjs    # 책 안: 같은 대상의 연도 충돌, 요약↔본문
python3 t1.py <스크린샷 폴더>   # 390·1280 가로 넘침 없음
python3 checks/pdfcheck.py print/<pfx>_a4.pdf   # 숨은 표지 0, Type 3 글꼴 없음, 북마크·제목 정보, 거의 빈 쪽
grep -E "[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}" dist/index.html   # 개인 정보 없음
```
- 예외: `pdfcheck`의 실패 가운데 DEFECTS에 열려 있는 공통 인쇄 결함(P-01~P-07)에 해당하는 것은 출간을 막지 않는다. 보고에 적고, 정비에서 고친다.
- 실패하면 고칠 수 있는 것은 고치고 다시 돌린다. 서술 문제면 `library-write`의 규칙대로, 구조 문제면 사용자에게 알리고 `library-plan`으로 돌린다.
- 검사가 틀렸다고 판단되면(오탐) 검사를 고치거나 예외를 그 책의 SPEC에 근거와 함께 적는다. 조용히 무시하지 않는다.

## 2. 독립 검수 (모든 책 필수)

작업 맥락을 모르는 별도 에이전트에게 맡긴다(Agent 도구, 새 에이전트. fork가 아니다).

**넘겨주는 것(이것만):**
- 출간본에서 뽑은 장별 본문 텍스트. HTML의 DATA에서 장마다 부, 제목, 연도, 요약, 절, 문단, 그 시대의 말, 작품을 텍스트로 뽑아 파일로 준다. 머리말과 서가 목록 전체도 함께 준다.
- A4 PDF 경로
- `SPEC.md`(평가어 목록, 시선, 입장 기준이 들어 있다)
- `review/지시문_아첨억제.txt`(사용자의 검수 지시문)
- 아래 지시

**나누기:** 검수자 한 명이 웹으로 확인할 수 있는 양에는 한도가 있다. 리허설에서 장 7개(약 3만 자)가 한 명의 한도였다. 그래서 장 7~10개씩 나누어 여러 검수자에게 맡긴다. 머리말·구성·책 전체 충돌을 보는 검수자 한 명을 따로 둔다. 이 검수자에게는 모든 장의 요약과, 연도가 든 문장 목록(`checks/consistency.mjs` 출력 포함)을 준다.

**검수 지시(그대로 전달):**
```
당신은 이 책을 처음 보는 검수자다. 첨부한 지시문 가운데 1(질문 분류·전제 점검), 2-1·2-2·2-4·2-6, 4, 5, 6의 [사실]·[해석][평가]·[비평] 규칙을 적용하라. 지시문 첫머리의 다른 글 제목 줄과 마지막 줄의 응답 형식 지시는 무시한다.
맡은 범위: (부·장 목록)
확인 순서(한도 안에서 앞에서부터):
 a) 책 안의 충돌: 같은 사실이 장·요약·서가에서 다르게 쓰인 곳
 b) 서지와 연구사: 본문과 서가에 나온 연구서의 저자·연도·제목, 학자 귀속
 c) 단정적 최상급과 '최초·유일·가장'
 d) 출처 없는 수치(사상자, 인구, 부수, 판매량)
 e) 그 밖의 연도·날짜
 f) 직접 인용문: 원문과 맞는가, 다른 글의 문장이 섞이지 않았는가
범위:
1) 연도·숫자·날짜가 들어간 문장: 사실 여부, 책 안의 충돌.
2) 서지: 실재 여부. 검색으로 확인하고, 확인하지 못하면 '확인 못함' 목록에 둔다.
3) 해석의 갈림·흔한 오해: 학자 이름과 연도가 본문에 있는가(작품 목록에만 있으면 지적), 해석이 사실처럼 쓰인 곳.
4) 시선과 말: SPEC의 평가어 목록이 서술자 문장에 쓰였는가(이것은 지적). 그 밖의 평가 표현은 '형식적' 강도로만 적는다. 관점·여러 목소리 책이면 매 장 바깥 점검이 있는가.
5) 머리말·요약과 실제 구성의 일치. 장 첫머리 요약과 본문이 맞는가. 인쇄본이 화면판에 없는 것을 말하지 않는가.
6) 교차 참조([[id]]가 맞는 장을 가리키는가), 외래어 표기(머리말이 약속한 규칙), '그 시대의 말' 목록의 말이 그 시대의 말인가.
7) 인쇄본 형식(PDF를 받은 검수자만): 숨은 표지, 글꼴 형식, 북마크, 거의 빈 쪽, 고아 제목.
출력:
 - 지적 표 하나. 열은 [번호, 위치(부·장·절 또는 쪽), 지적, 근거 종류(사실/통설/추론/추측, 본문 대조는 '사실(본문 대조)', 기억에 의존했으면 '기억 기반'을 덧붙임), 확신도(그 지적이 맞을 가능성: 높음/중간/낮음), 강도(고치지 않으면 생기는 문제의 크기: 강/약/형식적), 고칠 안].
 - 서지 확인 기록(지적 아님): 확인한 서지와 출처 URL.
 - 확인 못함: 확인하려 했으나 확인하지 못한 사실과 서지. 기억과 어긋나지 않으면 지적으로 세지 않는다.
 - 검토하지 않음: 다루지 못한 범위와 그 이유(도구 한도 포함). 검토하지 않은 것을 통과로 치지 않는다.
웹으로 확인한 것은 출처 URL을 단다. 지적을 지어내지 마라.
```
- 검수 결과를 받으면 DEFECTS의 그 책 절에 옮긴다. 번호는 `<id>-NN`, 상태는 `열림`이다. 확인 못함 목록은 UNVERIFIED로 옮긴다.
- 검수자의 지적도 틀릴 수 있다. 확신도 '높음'인 사실 지적 가운데 고치기 전에 출처를 다시 보지 않은 것은 처리 단계에서 확인한다.

## 3. 결함 처리

1. **높음:** 고친다. 고칠 수 없거나 고치지 않을 이유가 있으면 `보류(이유)`로 두고 사용자에게 묻는다.
2. **중간·낮음:** 확인하고 고친다. 확인할 수 없으면 본문을 좁혀 쓰거나 '전해진다'로 바꾸고 UNVERIFIED에 남긴다.
3. **기각:** 검수 지적이 틀렸다고 판단하면 근거를 적고 `기각(이유)`로 둔다. 기각도 보고에 싣는다.
4. 고친 뒤 §1 검사를 다시 돌린다. 고친 범위가 크면(장 하나 이상을 다시 쓴 경우) 그 부분만 다시 독립 검수한다.
5. 같은 종류의 결함이 다른 책에도 있을 수 있으면(엔진·인쇄·공통 실수) 공통 결함(E·P·L)으로 올린다. 다른 책에도 있는지 검사한다.

## 5. 서가 병합과 업로드

1. **등록부:** `library/books.json`에 그 책을 넣는다.
   - 들어갈 칸: id, 제목(`t`), 부제(`sub`), 범위(`span`), 설명(`desc`), 묶음(`grp`), 장·부 수(`ev`, `parts`), 읽는 법 여부(`guide`), 색(`color`, `colorDark`), PDF 이름(`pdf`), 소스 위치(`source`).
   - 새 묶음이 필요하면 `grp`에 새 이름을 쓴다. 서가는 묶음을 자동으로 만든다.
2. **병합:** `python3 library/merge.py`(서재가 여럿이면 `--reg <등록부>`). 기존 책의 HTML이 작업 환경에 없으면 먼저 `python3 library/extract.py <서가 HTML>`로 공개 서가에서 꺼낸다. 병합 도구가 하는 일:
   - 책 사이 일관성 검사(`library/xcheck.py`)
   - 권수 문구, 색, 카드, PDF 버튼 생성
   - 공통 글꼴 생성
3. **서가 확인:**
   - 서가 HTML을 390·1280에서 연다. 모든 카드의 읽기와 읽는 법, PDF 링크가 맞는지 본다.
   - 새 책 안에서 몇 장을 넘겨 본다.
   - 책 사이 충돌이 보고되면 어느 쪽이 맞는지 확인하고 두 책 모두 고친다(정비).
4. **업로드(`history-all`):**
   - 저장소 구성은 `index.html`(서가 전체를 담은 HTML)과 `pdf/`다.
   - PDF 이름은 제목에서 공백을 뺀 `<제목>_A4.pdf`(예: `지하드주의의눈_A4.pdf`)이고, 등록부의 `pdf`와 같아야 한다. `print/<pfx>_a4.pdf`를 이 이름으로 복사한다.
   - 사용자에게 보내는 단독 책 HTML은 `<제목>.html`이다. 저장소에는 올리지 않는다.
   - 올리는 것은 이번 작업에서 새로 생성된 HTML(새로 병합한 `index.html`)과 그 책의 A4 PDF(`pdf/<제목>_A4.pdf`)뿐이다. zip, 소스, 스크린샷, 기타 파일은 올리지 않는다.
   - 커밋 메시지 끝에 세션이 지정한 작성자 줄을 붙인다.
5. **엔진 저장소:** 소스, STATUS("출간 YYYY-MM-DD, 커밋 …"), DEFECTS, 등록부를 커밋한다. 새 변형을 썼으면 LIBRARY §4 실적표에 한 줄 더한다(개정 기록 포함).
6. **사용자에게:** 무엇이 올라갔는지, 링크, 열린 결함이 있으면 그 수와 이유를 알린다. 파일은 SendUserFile로 보낸다.

## 6. 정비 모드 (기존 책)

- **대상 고르기:** DEFECTS의 열린 항목을 책별·공통별로 묶는다. 공통 결함(엔진·인쇄)을 먼저 고쳐야 각 책의 재빌드가 한 번으로 끝난다.
- **소스가 있는 책:** `books/<id>/`에서 고치고 다시 빌드한다. 그 책의 템플릿이 오래된 판이면, 같은 결함을 그 판에서 최소한으로 고친다. 템플릿을 통째로 바꾸면 그 책의 화면이 달라질 수 있다.
- **소스가 없는 책:** `books/<id>/book.json`(출간본의 DATA)과 출간본의 템플릿 부분으로 다시 빌드한다. 본문을 고칠 때는 book.json의 `body`를 고친다. 인물 감지가 바뀌는 수정이면 감지를 다시 돌린다.
- **본문 정오:** 검수 지적마다 고친 문장과 근거를 DEFECTS의 `처리` 칸에 적는다. 같은 사실이 다른 장이나 다른 책에도 있는지 찾아 함께 고친다.
- **확인:** 정비한 책도 §1 검사를 모두 통과해야 하고, PDF는 새로 만든다. 업로드 규칙(§5.4)은 같다. 이번에 새로 생성된 HTML과 그 A4 PDF만 올린다.

## 하지 말 것

- 검수 없이, 또는 확신도 높은 결함이 열린 채로 출간하기
- 검수 결과를 DEFECTS에 적지 않고 넘어가기. 고친 것만 적고 보류·기각을 빼기
- 검수자에게 작업 맥락이나 "잘 썼다"는 정보를 주기
- 업로드 규칙 밖의 파일(zip, 소스, 스크린샷)을 history-all에 올리기
- 등록부를 거치지 않고 서가 HTML을 손으로 고치기
